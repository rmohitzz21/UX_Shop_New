## 2. Admin order status change — orders disappear bug

**Problem:** After changing an order's status in the admin panel, all orders except `pending` would vanish from the table.

**Root cause:** `normalizeStatus('')` returns `'pending'` (because `'' || 'pending'` defaults to `'pending'`). When the status filter dropdown was on "All Orders" (empty value), the filter silently became `'pending'` after each reload, hiding all non-pending orders.

**Fix:** `admin/admin-dashboard.js` — changed the filter line to skip `normalizeStatus` when the raw value is empty:
```js
// Before
const filter = normalizeStatus(document.getElementById('order-status-filter')?.value || '');

// After
const filterRaw = (document.getElementById('order-status-filter')?.value || '').trim();
const filter = filterRaw ? normalizeStatus(filterRaw) : '';
```

## 4. Sign-in / Sign-up API audit & fixes

**Files:** `script.js`, `signin.php`

### Bugs found and fixed

#### Bug 1 — JS password validation stricter than PHP API
- **JS** required: uppercase + lowercase + number + 8 chars (regex: `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)...`)
- **PHP API** (`api/auth/signup.php`) only checks: `strlen($password) < 8`
- **Result:** Passwords like `mypassword1` were blocked by JS but would be accepted by the API
- **Fix:** Removed the `validatePassword` regex check in `handleSignUp`; now JS only enforces the 8-char minimum, matching the API

#### Bug 2 — `handleSignInRedirect` allowlist too narrow
- After login, users from `wishlist.php`, `product.php`, `bundles.php`, `freebies.php`, `search.php` would land on `index.php` instead of their original destination
- **Fix:** Added all missing pages to the `allowedPages` array in `handleSignInRedirect`

#### Bug 3 — Signup doesn't preserve `?redirect=` param
- If user came from `wishlist.php?redirect=` → signup → signin, the redirect destination was lost
- **Fix:** `handleSignUp` success redirect now reads `?redirect=` from the current URL and forwards it to `signin.php`

#### Bug 4 — signin.php silently drops `?message=` param
- After signup, `handleSignUp` redirects to `signin.php?message=Account created!...` but signin.php had no code to display it
- **Fix:** Added a `$_GET['message']` success alert block in `signin.php`
